# ATM Cash Intelligence — Система прогнозирования остатков и оптимизации инкассации

> **Хакатон SQB · Тема №6** — Прогнозирование остатков в банкоматах  
> Предотвращение cash-out и оптимизация маршрутов инкассации средствами Machine Learning

---

## Проблема

Банки ежедневно теряют деньги и клиентов из-за устаревшей схемы управления наличными в ATM:

- Пополнение по историческому среднему — без учёта праздников, зарплатных дней и сезонности
- Реактивный подход: банкомат уже пуст, клиент уже недоволен
- Инкассационные маршруты не оптимизированы — машины проезжают лишние километры
- Избыточная загрузка наличными замораживает оборотный капитал банка

**Результат:** cash-out, потеря лояльности клиентов, сотни миллионов сум в замороженных остатках.

---

## Решение

**ATM Cash Intelligence** — интеллектуальная платформа реального времени для мониторинга, прогнозирования и оптимизации ATM-сети.

Система работает в трёх направлениях:

1. **Предсказывает** баланс каждого ATM на 24 часа вперёд с точностью MAPE 6.8%
2. **Классифицирует** риск cash-out с ROC-AUC 0.9903
3. **Строит** оптимальный маршрут инкассации по ML-приоритету, а не по расписанию

## Ключевые результаты модели

| Метрика | Validation | Test |
|---|---|---|
| Regression MAE | 27.2 млн сум | 27.7 млн сум |
| Regression RMSE | 51.3 млн сум | 51.5 млн сум |
| Regression MAPE | **6.81%** | **6.92%** |
| Classifier ROC-AUC | **0.9903** | **0.9874** |
| Classifier AUC-PR | **0.9410** | **0.9184** |

Горизонт прогноза: **24 часа (12 шагов по 2 часа)**.  
Порог cash-out: остаток ниже **20%** ёмкости ATM.

Модель стабильна на обоих срезах — разрыв между validation и test минимален, переобучения нет.

Каждый тик симулятора:
1. Берёт следующую строку из CSV (шаг = 2ч)
2. Передаёт состояние ATM в `Predictor`
3. `Predictor` строит признаки через `features.make_features()` — тот же код, что и при обучении
4. XGBoost делает инференс за < 1 мс
5. Результат транслируется всем подключённым клиентам через WebSocket

## ML-подход

### Модели

**XGBRegressor** — предсказывает абсолютный баланс ATM через 24 часа  
**XGBClassifier** — предсказывает вероятность cash-out (остаток < 20% ёмкости)

Обе модели обучены на одном датасете, но с разными таргетами. Признаки идентичны — нет расхождения между обучением и продом.

### Feature Engineering

Для каждого ATM в момент инференса формируется вектор из 30+ признаков:

| Группа | Признаки |
|---|---|
| Лаги баланса | balance\_lag\_1, \_3, \_6, \_12, \_24 (шаг 2ч) |
| Скользящие | rolling\_mean\_6/12/24, rolling\_std\_6/12 |
| Динамика | burn\_rate (расход за 6 периодов), time\_to\_empty (часов до нуля) |
| Инкассации | incassation\_count\_12/24, hours\_since\_last\_incassation |
| Календарь УЗ | is\_salary\_day, is\_near\_salary, is\_holiday, is\_pre\_holiday, season\_factor |
| Профиль ATM | atm\_profile (рынок / метро / жилой / офис / ...) |
| Время | hour, day\_of\_week, is\_weekend, month, week\_of\_year |

Признаки строятся в `api/core/features.py` и полностью совпадают с `train_model.py` — дрейфа фич нет.

### Почему XGBoost, а не LSTM или Prophet

| Критерий | XGBoost | LSTM | Prophet |
|---|---|---|---|
| ROC-AUC на наших данных | **0.990** | хуже при коротких рядах | хуже без тюнинга |
| Скорость инференса | **< 1 мс** | > 100 мс | > 50 мс |
| Интерпретируемость | **feature importance** | чёрный ящик | частично |
| Развёртывание | **1 файл .joblib** | TensorFlow / PyTorch | отдельный стек |
| Стабильность train/test | **разрыв < 0.5%** | склонен к переобучению | зависит от тренда |

LSTM и Prophet были проверены на тех же данных — XGBoost выиграл по всем критериям.

## Оптимизация маршрутов инкассации

1. **Фильтрация** ATM по статусу (`critical` / `warning`) и ML-риску (`HIGH` / `MEDIUM`)
2. **Приоритетный score** = f(баланс %, ML-вероятность cash-out, часы до опустошения)
3. **Кластеризация** по количеству машин инкассации
4. **2-opt TSP** — локальная оптимизация маршрута внутри кластера
5. **OSRM** (опционально) — реальные дорожные дистанции и геометрия маршрута

**Результат:** инкассационные машины едут туда, где ML видит реальный риск, а не по расписанию.

## Экономический эффект

Endpoint `GET /api/baseline` сравнивает ML-подход со стандартным банковским методом для каждого ATM:

- **Метод банка**: среднее снятие за неделю → план пополнения на 24ч
- **ML-метод**: прогноз XGBoost → рекомендация по фактической потребности

```
ML снижает загрузку = план банка − рекомендация ML
```

Если система показывает "ML снижает загрузку 518 млн сум" по одному ATM — это означает, что банк отправил бы на 518 млн сум больше наличных, чем реально нужно. Эти деньги остаются в обороте банка.

## Особенности для Узбекистана

- **Зарплатный календарь**: пики спроса 10-го и 25-го числа (±2 дня) встроены в признаки
- **Государственные праздники**: Навруз, День независимости, Курбан-хайит, Руза-хайит и другие
- **Сезонность**: квартальный коэффициент спроса
- **Профили ATM**: рынки, метро, жилые кварталы, офисные центры — разные паттерны спроса
- **Геоданные**: реальные границы районов Ташкента (`tashkent_districts.geojson`)
- **Валюта**: все суммы в узбекских сумах (UZS)

## Быстрый старт

### Требования

- Python 3.10+
- pip

### Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/grxt777/dominify-sqb.git
cd dominify-sqb

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Запустить сервер (модели уже обучены и сохранены)
```

```bat
start.bat
```
